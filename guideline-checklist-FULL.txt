1
เตรียมเครื่องมือ + สมัครบัญชีให้ครบก่อน คุณทำเอง
ทุกอย่างฟรี · ทำให้เสร็จก่อนค่อยไปขั้นถัดไป จะได้ไม่ติดกลางทาง
▶
ขั้นนี้คือ "ซื้อของเข้าครัว" ก่อนทำกับข้าว — สมัครบัญชีบริการที่ใช้ และติดตั้งโปรแกรมบนเครื่อง 2–3 ตัว แต่ละอันคืออะไรอธิบายไว้ในแต่ละข้อแล้ว
ก) ติดตั้งโปรแกรมบนเครื่องคอมพิวเตอร์
1.1 ติดตั้ง Node.js เวอร์ชัน LTS จาก nodejs.org (กด Next ไปเรื่อย ๆ) คือโปรแกรมที่ทำให้เครื่องรันโค้ดของเว็บได้ จำเป็นถ้าอยากลองเปิดเว็บบนเครื่องตัวเองก่อน (localhost) · ตรวจว่าติดตั้งสำเร็จโดยเปิด Command Prompt พิมพ์ node -v ต้องขึ้นเลขเวอร์ชัน
1.2 ติดตั้ง Git จาก git-scm.com เครื่องมือส่งโค้ดจากเครื่องขึ้นไปเก็บบน GitHub · ตรวจด้วย git --version
1.3 (แนะนำ) ติดตั้ง VS Code จาก code.visualstudio.com โปรแกรมเปิด/แก้ไฟล์โค้ด ใช้ดูโปรเจกต์สะดวกกว่า Notepad — ไม่บังคับ แต่ช่วยได้มาก
ข) สมัครบัญชีบริการออนไลน์ (ฟรีทั้งหมด)
1.4 สมัคร GitHub ที่ github.com ที่เก็บโค้ดออนไลน์ — เปรียบเหมือน Google Drive ของโค้ด · Vercel จะดึงโค้ดจากที่นี่ไปรัน
1.5 สมัคร Supabase ที่ supabase.com (กด Sign in with GitHub ได้เลย) ฐานข้อมูล + ระบบล็อกอินสำเร็จรูป — เก็บตัวเลขโฆษณา รายชื่อบัญชี ผู้ใช้ ฯลฯ
1.6 สมัคร Vercel ที่ vercel.com (กด Continue with GitHub) ที่โฮสต์เว็บ — เอาโค้ดจาก GitHub มาทำให้เปิดได้จริงบนอินเทอร์เน็ต ฟรีพอสำหรับงานนี้
1.7 สมัคร cron-job.org ที่ cron-job.org "นาฬิกาปลุก" ฟรี — คอยยิงเข้าเว็บทุก 5 นาทีให้ระบบดึงข้อมูลใหม่อัตโนมัติ
ค) บัญชีฝั่งแพลตฟอร์มโฆษณา (เตรียมเฉพาะตัวที่จะใช้)
1.8 Meta: มี Business Manager ที่เห็นบัญชีโฆษณาลูกค้า + สิทธิ์ Admin ถ้ายังไม่มี Business Manager ให้สร้างก่อน แล้วให้ลูกค้าแชร์ Ad Account เข้ามา
1.9 Google: มีบัญชี Google Ads แบบ MCC (บัญชีศูนย์กลางที่คุมหลายบัญชี) + บัญชี Google Cloud Console MCC = My Client Center บัญชีแม่ที่ดูบัญชีลูกค้าหลายตัวได้ · Google Cloud ใช้ขอสิทธิ์เข้า API
1.10 TikTok: สมัคร TikTok for Developers + เข้าถึง TikTok Ads Manager ของลูกค้า สำหรับ GMV Max ต้องเข้าถึง TikTok Shop ของลูกค้าด้วย
ยังไม่พร้อมครบทุกแพลตฟอร์มก็ไม่เป็นไร — เริ่มจากตัวที่พร้อมก่อน (เช่น Meta) แล้วค่อยเพิ่มทีหลังได้ ระบบไม่พังกัน
2
เอาโปรเจกต์ลงเครื่อง + รู้จักโฟลเดอร์/เทมเพลต คุณทำเอง
เห็นภาพว่าในโฟลเดอร์มีอะไรบ้าง อะไรห้ามแตะ และโฟลเดอร์ไหน "โผล่มาเอง" ทีหลัง
▶
ตอนนี้ในเครื่องคุณยังไม่มีโฟลเดอร์โปรเจกต์ และจะไม่มีใครส่งไฟล์ให้ — คุณต้อง "สร้างโปรเจกต์ขึ้นมาเอง" จากศูนย์ ข้อ ก) ด้านล่างจะพาสร้างโครงเปล่า ๆ ด้วยเครื่องมือมาตรฐาน แล้วเติมโฟลเดอร์ที่เหลือเข้าไปให้ครบตามผัง
ก) สร้างโปรเจกต์ขึ้นมาเองตั้งแต่ศูนย์
เราใช้คำสั่ง create-next-app ซึ่งเป็นตัวสร้างโครงเว็บ Next.js อัตโนมัติ — มันจะปั้นโฟลเดอร์ src/app/ , public/ , ไฟล์ package.json , .gitignore และติดตั้ง node_modules/ ให้เสร็จในคำสั่งเดียว จากนั้นค่อยสร้างโฟลเดอร์ที่เหลือเองอีกนิด
2.1 เปิด Command Prompt / Terminal แล้ว cd ไปยังที่ที่อยากเก็บงาน เช่นหน้า Desktop
คัดลอก
cd Desktop
2.2 สร้างโครงโปรเจกต์ชื่อ dashboard ด้วยคำสั่งนี้ (มันจะถามตั้งค่า ตอบตามกล่องสีเหลืองด้านล่าง)
คัดลอก
npx create-next-app@latest dashboard
ตอบคำถามที่มันถามดังนี้: TypeScript? → No · ESLint? → Yes · Tailwind CSS? → Yes · `src/` directory? → Yes (สำคัญ) · App Router? → Yes (สำคัญ) · Turbopack? → Yes · import alias? → กด Enter ผ่าน
คำว่า dashboard คือชื่อโฟลเดอร์ที่จะถูกสร้าง — ในคู่มือนี้เราเรียกว่า dashboard ตลอด
2.3 เข้าไปในโฟลเดอร์ที่เพิ่งสร้าง แล้วเปิดด้วย VS Code
คัดลอก
cd dashboard
code .
2.4 สร้างโฟลเดอร์ที่ตัวสร้างอัตโนมัติ ยังไม่ได้ทำให้ (templates, components, lib, migrations) ด้วยคำสั่งนี้
คัดลอก
mkdir public/templates src/components src/lib supabase
บน Windows ถ้าใช้ Command Prompt ให้สลับเป็น backslash และทำทีละบรรทัด เช่น mkdir public\templates ... ส่วนโฟลเดอร์ย่อย migrations พิมพ์ mkdir supabase\migrations
2.5 ติดตั้งแพ็กเกจเสริมที่ระบบต้องใช้ (ตัวเชื่อม Supabase)
คัดลอก
npm install @supabase/supabase-js
สำคัญที่สุดของขั้นนี้: ตอนนี้คุณได้แค่ "โครงเปล่า" ของเว็บ Next.js — ตัวที่ทำให้มันกลายเป็นแดชบอร์ดจริงคือ ไฟล์โค้ดของระบบ ที่ต้องไปวางในแต่ละโฟลเดอร์ ได้แก่ หน้า/เอพีไอใน src/app/ (เช่น api/sync , api/metrics ), ตัวเชื่อมแพลตฟอร์มใน src/lib/ , ไฟล์ SQL 5 ไฟล์ใน supabase/migrations/ และไฟล์เทมเพลต 4 ไฟล์ + โลโก้ใน public/templates/ (เทมเพลตนี้ คุณต้องออกแบบ/เขียนเอง — ดูรายละเอียดด้านล่าง) — เตรียมไฟล์เหล่านี้ให้ครบตามผังด้านล่างก่อนไปขั้นถัดไป
ข) ผังโฟลเดอร์ "ตอนเสร็จแล้ว" (ใส่ไฟล์ครบควรเห็นแบบนี้)
dashboard/ ← โฟลเดอร์โปรเจกต์ (รากของทุกอย่าง)
├─ public/
│ └─ templates/ ← หน้า dashboard ที่ "คุณต้องออกแบบ/สร้างเอง" (ตั้งชื่อไฟล์ตามนี้เป๊ะ)
│ ├─ meta-dashboard.html ← คุณสร้างเอง
│ ├─ google-dashboard.html ← คุณสร้างเอง
│ ├─ tiktok-dashboard.html ← คุณสร้างเอง
│ ├─ tiktok-gmvmax-dashboard.html ← คุณสร้างเอง
│ └─ logo-M.png ← โลโก้หน้า login (คุณใส่รูปเอง)
├─ src/
│ ├─ app/ ← หน้าเว็บ + API ทั้งหมด (/api/sync, /api/metrics ...)
│ ├─ components/ ← ชิ้นส่วนหน้าจอที่ใช้ซ้ำ
│ └─ lib/ ← โค้ดเชื่อม Meta/Google/TikTok + Supabase
├─ supabase/
│ └─ migrations/ ← ไฟล์ SQL 5 ไฟล์ (0001 ถึง 0005) ใช้ในขั้น 4
├─ .env.local.example ← รายชื่อ "ตัวแปรลับ" ทั้งหมด (ดูเป็นตัวอย่าง)
├─ package.json ← รายชื่อแพ็กเกจที่ต้องติดตั้ง
├─ vercel.json ← ตั้งค่า cron สำรองของ Vercel
└─ .gitignore ← กันไฟล์ลับ/ไฟล์ใหญ่ ไม่ให้ขึ้น Git
* ชื่ออาจต่างเล็กน้อยตามเครื่อง แต่โครงหลัก public / src / supabase ต้องมีครบ
โฟลเดอร์/ไฟล์ที่ "โผล่มาเอง" ทีหลัง (ไม่ต้องสร้าง — ระบบสร้างให้)
node_modules/ ← โผล่หลังรัน npm install (รวมแพ็กเกจ ใหญ่มาก ห้ามแก้)
.next/ ← โผล่หลังรัน npm run dev / build (ไฟล์ที่ระบบสร้างเอง)
.git/ ← โผล่หลังรัน git init (เก็บประวัติเวอร์ชันโค้ด)
.env.local ← คุณสร้างเองเฉพาะถ้าจะรันบนเครื่อง (ก็อปจาก .env.local.example)
สรุปกฎทอง: 3 ตัวบนนี้ (node_modules, .next, .git) ถูกตั้งใน .gitignore ให้ไม่ขึ้น GitHub อยู่แล้ว ปล่อยมันไว้เฉย ๆ ไม่ต้องไปยุ่ง
2.6 เปิดโฟลเดอร์โปรเจกต์แล้วไล่เทียบกับผังด้านบน — ยืนยันว่ามี public/ , src/ , supabase/ ครบ
2.7 สร้างไฟล์เทมเพลตทั้ง 4 ไฟล์ใน public/templates/ ด้วย ชื่อตามตารางด้านล่างให้ตรงเป๊ะ (สร้างเป็นไฟล์ .html เปล่า ๆ ไว้ก่อนก็ได้ แล้วค่อยออกแบบหน้าตาทีหลัง)
เรื่อง "เทมเพลต" — คุณต้องออกแบบและสร้างเอง
เทมเพลตคือ "หน้าตา dashboard" ที่ลูกค้าเห็นตอนเปิดรายงาน — ไม่มีใครทำมาให้ คุณต้องออกแบบและเขียนเองทั้งหมด โดยสร้างเป็นไฟล์ HTML วางไว้ใน public/templates/ ระบบจะ เลือกเทมเพลตให้อัตโนมัติตามแพลตฟอร์มของบัญชี ตอนเปิดรายงาน (ขั้นที่ 14) โดยโหลดไฟล์เข้ามาแสดงใน iframe พร้อมส่งพารามิเตอร์ ?sources= (ไอดีบัญชี), &token= และ &ro=1 (โหมดอ่านอย่างเดียว) มาให้ — หน้าที่ของเทมเพลตคือยิงไปดึงตัวเลขจริงจาก /api/metrics แล้วเอามาวาดเป็นกราฟ/ตารางเอง
กฎเหล็กของชื่อไฟล์: ระบบมองหาไฟล์ตาม "ชื่อเป๊ะ" ในตารางนี้เท่านั้น ถ้าตั้งชื่อผิดแม้แต่ตัวเดียว (เช่น Meta-Dashboard.html หรือ meta_dashboard.html ) ระบบจะหาไม่เจอและเปิดหน้า dashboard ไม่ได้ — ต้องเป็นตัวพิมพ์เล็กและขีดกลางตามนี้เป๊ะ

เอาโค้ดโปรเจกต์ขึ้น GitHub คุณทำเอง
เพื่อให้ Vercel ดึงไปรันได้ · ทำในโฟลเดอร์โปรเจกต์
▶
เปิด Command Prompt / PowerShell แล้วพิมพ์ cd ตามด้วยที่อยู่โฟลเดอร์โปรเจกต์ (หรือคลิกขวาในโฟลเดอร์ → Open in Terminal) จากนั้นทำตามนี้
3.1 สร้าง repo ว่าง ๆ บน GitHub (กดปุ่ม New repository ตั้งเป็น Private)
3.2 ในโฟลเดอร์โปรเจกต์ พิมพ์คำสั่งทีละบรรทัด
คัดลอก
git init
git add .
git commit -m "first commit"
หลังคำสั่งนี้ในโฟลเดอร์จะเริ่มมี .git/ โผล่มาเอง (ประวัติเวอร์ชัน) — ปล่อยไว้ ไม่ต้องยุ่ง
ไฟล์ .gitignore ในโปรเจกต์กัน node_modules , .next และ .env.local (ไฟล์รหัสลับ) ไม่ให้หลุดขึ้น GitHub ไว้ให้แล้ว — ปลอดภัย
3.3 เชื่อมกับ repo บน GitHub แล้ว push (เปลี่ยน URL เป็นของ repo คุณ ตามที่หน้า GitHub บอก)
คัดลอก
git remote add origin https://github.com/<ชื่อคุณ>/<ชื่อ-repo>.git

Google Ads ต้องการ 5 ค่า เพราะมันออกแบบมาให้ปลอดภัยมาก ระบบจะเอา Refresh Token ไปแลกเป็นรหัสชั่วคราวเองทุกครั้งที่ดึงข้อมูล (คุณไม่ต้องทำอะไรเพิ่มหลังตั้งเสร็จ)

7.4 จดเลขบัญชี MCC 10 หลัก (ตัดขีด - ออก เช่น 123-456-7890 → 1234567890) → GOOGLE_ADS_LOGIN_CUSTOMER_ID

13
ตั้งค่าโดเมน + ระบบล็อกอิน (Auth) คุณทำเอง
ทำให้หน้าหลังบ้านต้องล็อกอินก่อน + (ถ้าต้องการ) ใช้โดเมนของตัวเอง
▶
ระบบล็อกอินทำงานยังไง: หน้าหลังบ้านทั้งหมด (Home, Sources, Reports, Users) ถูก "ล็อก" ไว้ — โค้ดจะเช็คว่ามีการล็อกอิน (session) ของ Supabase ไหม ถ้า ไม่มี จะเด้งไปหน้า /login โดยอัตโนมัติ ส่วนลิงก์รายงานที่แชร์ให้ลูกค้า ( /r/<token> ) เปิดดูได้โดย ไม่ต้อง ล็อกอิน (อ่านอย่างเดียว) · ก่อนสร้างผู้ใช้ ให้ชี้ระบบ Auth ของ Supabase มาที่โดเมนของคุณก่อน
ก) ผูก Auth ของ Supabase กับโดเมน (จำเป็น)
13.1 เปิด Supabase → Authentication → URL Configuration
13.2 ตั้ง Site URL = โดเมนของคุณจากขั้น 9 (เช่น https://ชื่อโปรเจกต์.vercel.app ) ค่านี้คือ "บ้านหลัก" ที่ระบบ Auth ใช้อ้างอิงตอนล็อกอิน/รีไดเร็กต์
13.3 ในช่อง Redirect URLs เพิ่ม https://<โดเมนของคุณ>/** แล้ว Save อนุญาตให้เด้งกลับมาที่ทุกหน้าในโดเมนนี้ได้หลังล็อกอิน
ข) ใช้โดเมนของตัวเอง + verify domain (ไม่บังคับ — ข้ามได้ถ้าใช้ .vercel.app)
ถ้าอยากให้ลิงก์เป็นแบรนด์ตัวเอง เช่น dashboard.yourcompany.com แทน .vercel.app — Vercel จะให้ค่า DNS มาชุดหนึ่งให้เอาไปใส่ที่ผู้ให้บริการโดเมน แล้วรอ "ยืนยันโดเมน (verify)" สำเร็จ
13.4 Vercel → โปรเจกต์ → Settings → Domains → ใส่โดเมนที่ต้องการ → กด Add
13.5 Vercel จะโชว์ค่า DNS (เช่น CNAME หรือ A record ) → เอาไปใส่ในหน้าจัดการโดเมนของผู้ให้บริการ (เช่น GoDaddy, Cloudflare) verify domain = ขั้นที่ Vercel ตรวจว่าค่า DNS ตั้งถูก แล้วเปลี่ยนสถานะเป็น Valid (อาจรอ 5 นาที–ไม่กี่ชั่วโมง)
13.6 เมื่อโดเมนขึ้น Valid แล้ว → กลับไป แก้ Site URL + Redirect URLs ใน Supabase (ข้อ 13.2–13.3) ให้เป็นโดเมนใหม่
ถ้าลืมอัปเดต Site URL ให้ตรงกับโดเมนที่ใช้จริง การล็อกอินอาจเด้งกลับผิดที่ หรือขึ้น error เรื่อง redirect — เช็คจุดนี้ก่อนเสมอถ้าล็อกอินมีปัญหา
ค) เรื่องอีเมลยืนยัน (เข้าใจไว้ ไม่ต้องทำอะไรเพิ่ม)
ผู้ใช้ที่สร้างผ่านเมนู Users ในเว็บ (หรือผ่าน Supabase แบบ Add user) จะถูกตั้งเป็น ยืนยันอีเมลแล้วอัตโนมัติ — ล็อกอินได้ทันทีโดยไม่ต้องรอกดลิงก์ยืนยันในเมล สะดวกสำหรับทีมงาน
13.7 ทดสอบ: เปิด https://<โดเมนของคุณ>/home ในหน้าต่างไม่ล็อกอิน (incognito) → ต้องถูกเด้งไป /login = ระบบกันถูกต้อง
ง) ล็อกให้เข้าได้เฉพาะอีเมลบริษัท (ไม่บังคับ — แนะนำถ้าอยากกันคนนอก)
เข้าใจค่าเริ่มต้นก่อน: ตามปกติระบบ ไม่ได้กรองโดเมนอีเมล — ใครก็ตามที่คุณกดเพิ่มในเมนู Users จะล็อกอินได้ทั้งหมด รวมถึง Gmail ถ้าอยากให้ "ต่อให้มีรหัสผ่าน แต่ถ้าไม่ใช่เมลบริษัทก็เข้าไม่ได้" ต้องเติมการเช็กโดเมนเองตามด้านล่าง (เปลี่ยน yourcompany.com เป็นโดเมนของคุณ)
เช็ก 2 จุด เพื่อให้กันได้สนิท: จุดที่ 1 กันตอน "ล็อกอิน" (สำคัญสุด — กันแม้บัญชีจะถูกสร้างไปแล้ว), จุดที่ 2 กันตั้งแต่ "ตอนสร้างผู้ใช้" (กันไม่ให้เผลอเพิ่มเมลนอกโดเมนตั้งแต่แรก)
13.8 จุดที่ 1 — กันตอนล็อกอิน: เปิดไฟล์ src/app/(app)/layout.js หาบรรทัดที่ได้ session มาแล้ว (ตรงที่เช็คว่า if (!session) router.replace("/login") ) แล้ว แทรกโค้ดนี้ต่อทันที
คัดลอก
// ── ล็อกเฉพาะอีเมลบริษัท ──
const ALLOWED_DOMAIN = "yourcompany.com"; // ← เปลี่ยนเป็นโดเมนบริษัทคุณ
const userEmail = (session.user?.email || "").toLowerCase();
if (!userEmail.endsWith("@" + ALLOWED_DOMAIN)) {
sb.auth.signOut(); // เตะออกจากระบบทันที
router.replace("/login?denied=1"); // เด้งกลับหน้า login
return;
}
ผลลัพธ์: ต่อให้มีคนถือรหัสผ่านของบัญชีที่ไม่ใช่โดเมนบริษัท (เช่น someone@gmail.com ) พอล็อกอินผ่าน Supabase ได้ ระบบจะ เตะออกทันที ก่อนเข้าหน้าหลังบ้าน
13.9 จุดที่ 2 — กันตั้งแต่ตอนสร้างผู้ใช้: เปิดไฟล์ src/app/api/users/route.js ในฟังก์ชัน POST หลังบรรทัดที่เช็ค if (!email || !password) แล้ว แทรกโค้ดนี้
คัดลอก
// ── อนุญาตเฉพาะอีเมลบริษัท ──
const ALLOWED_DOMAIN = "yourcompany.com"; // ← เปลี่ยนเป็นโดเมนบริษัทคุณ
if (!email.endsWith("@" + ALLOWED_DOMAIN)) {
return NextResponse.json(
{ ok: false, error: "domain_not_allowed" },
{ status: 400 }
);
}
ทำให้แม้แต่แอดมินก็เพิ่มผู้ใช้ที่ไม่ใช่โดเมนบริษัทไม่ได้ → ขึ้น error domain_not_allowed แทน
13.10 (ถ้าอยากให้ผู้ใช้เห็นเหตุผล) ที่หน้า src/app/login/page.js เพิ่มข้อความเตือนเมื่อ URL มี ?denied=1 เช่น "อนุญาตเฉพาะอีเมล @yourcompany.com เท่านั้น" ไม่บังคับ — แค่ให้ผู้ใช้รู้ว่าทำไมเข้าไม่ได้ ถ้าไม่ทำก็แค่เด้งกลับหน้า login เฉย ๆ
13.11 ทดสอบจริง: ลองเพิ่มผู้ใช้ Gmail แล้วล็อกอิน → ต้องเข้าไม่ได้ (ถูกเตะออก) · ส่วนเมลโดเมนบริษัท → เข้าได้ปกติ = ล็อกโดเมนสำเร็จ
ต้องแก้ทั้ง 2 จุดให้ ALLOWED_DOMAIN ตรงกัน และถ้ามีหลายโดเมนที่อนุญาต ให้เปลี่ยนเป็นลิสต์ เช่น ["yourcompany.com", "yourbrand.com"] แล้วเช็คด้วย .some(d => userEmail.endsWith("@" + d)) แทน
